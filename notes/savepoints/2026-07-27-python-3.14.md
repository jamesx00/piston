## Learned
- Piston doesn't bake runtimes into the API image — languages are built as standalone `.pkg.tar.gz` packages via `repo/Dockerfile` (a `debian:buster-slim` builder), then installed at runtime into a shared volume via `ppman`. Adding a language version = adding a `packages/<lang>/<version>/` dir, not touching `api/Dockerfile`.
- `./piston build-pkg <lang> <version>` rebuilds the `piston-repo-builder` image every time, then runs it against the repo to compile the package.
- On Apple Silicon (arm64) hosts, the builder image fails on `linux-headers-amd64` (no arm64-named equivalent) unless forced to amd64:
  `DOCKER_DEFAULT_PLATFORM=linux/amd64 ./piston build-pkg <lang> <version>`
  This runs the whole build (including compiling CPython from source) under QEMU emulation — noticeably slow.
